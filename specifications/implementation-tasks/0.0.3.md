# Implementation tasks

Check off each task only after its behavior is implemented and its relevant
tests pass. The order follows
[[specifications/milestones/0.0.3|Milestones and deliverables (v0.0.3)]].

## 1. Explain metadata lookup failures — BOOK-12

- [ ] Add distinct lookup results for no metadata and request failure.
- [ ] Preserve the scanned ISBN and the existing manual-entry fallback.
- [ ] Show an accessible no-result explanation in manual entry.
- [ ] Show distinct retry-oriented feedback for network or service failures.
- [ ] Keep barcode-validation errors separate from lookup errors.
- [ ] Test messages, accessibility text, and preserved ISBN values.

### Acceptance criteria

- A user knows why manual entry opened.
- Empty results and temporary failures do not show the same explanation.
- The scanned ISBN is never lost.

## 2. Investigate metadata coverage — BOOK-13

- [ ] Build a real-book test list that includes English, non-English, regional,
  old, and newly published editions.
- [ ] Obtain ISBNs and expected edition metadata for real books from the
  project owner; track the dependency in the BOOK-13 test-data request.
- [ ] Measure current Open Library coverage and record a reproducible baseline.
- [ ] Classify misses as source-data gaps, query limitations, response-mapping
  defects, edition-matching problems, or transient failures.
- [ ] Determine whether lookup failures correlate with language, region,
  publication age, provider data model, or request path.
- [ ] Evaluate alternate Open Library queries and external metadata providers.
- [ ] Compare edition accuracy, field quality, reliability, request limits,
  authentication, privacy, licensing, and maintenance cost.
- [ ] Write a decision request selecting the fallback approach.
- [ ] Define normalization and comparison rules for title, authors, language,
  publisher, and publication year without weakening exact-ISBN matching.

### Acceptance criteria

- The investigation is reproducible, uses a documented dataset large enough to
  expose coverage patterns, and includes ISBN `9789639884328` only as one
  regression sample.
- The decision request defines a measurable coverage target based on the
  dataset and evidence.
- Expected results come from owner-verified physical books, not from copying
  the external provider response into the assertions.
- The selected approach can return the exact scanned edition rather than a
  merely similar work.
- Provider constraints and operational requirements are documented.

## 3. Implement reliable provider fallback — BOOK-14

- [ ] Introduce a provider-independent metadata lookup interface.
- [ ] Keep Open Library as the primary provider unless the investigation
  justifies a different precedence.
- [ ] Query the selected fallback only when required.
- [ ] Accept a fallback result only when it matches the scanned ISBN.
- [ ] Reject title-specific and ISBN-specific special cases in production
  lookup logic.
- [ ] Preserve automatic saving of the first deterministic exact-edition
  result.
- [ ] Use BOOK-12 feedback when all providers miss or fail.
- [ ] Document configuration without committing credentials.
- [ ] Test primary success, fallback success, non-English metadata, total miss,
  provider errors, and mismatched-edition rejection.
- [ ] Add deterministic tests using reviewed, recorded provider responses.
- [ ] Add opt-in live contract tests that call the configured external
  providers for the owner-verified ISBN dataset.
- [ ] Keep live contract tests separate from the default deterministic suite so
  provider downtime or data edits do not make ordinary CI unreliable.

### Acceptance criteria

- The real-book test list meets the coverage target selected during the
  investigation.
- ISBN `9789639884328` passes through the same generic provider pipeline as all
  other ISBNs; its regression test contains no production special case.
- Provider precedence and error handling are deterministic.
- No fallback can silently save a different edition.
- Live tests report per-provider coverage and metadata mismatches against the
  owner-verified expected results.
