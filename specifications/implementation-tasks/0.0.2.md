# Implementation tasks

Check off each task as it is completed. The order follows
[[specifications/milestones/0.0.2|Milestones and deliverables (v0.0.2)]].

## 1. Validate ISBN values

- [x] Add a reusable ISBN validator for ISBN-10 and ISBN-13 values.
- [x] Normalize accepted ISBNs without changing their validity.
- [x] Validate the ISBN-13 check digit before a scanner result is looked up.
- [x] Validate a nonempty manual ISBN before Save.
- [x] Keep an empty manual ISBN valid.
- [x] Show a clear, accessible error for an invalid manual ISBN.
- [x] Add tests for valid ISBN-10, valid ISBN-13, invalid check digits, and
  empty ISBN values.

### Acceptance criteria

- Valid ISBN-10 and ISBN-13 values can be saved.
- A malformed or check-digit-invalid ISBN cannot be saved or looked up.
- A manual book with no ISBN still saves normally.
- A non-book EAN-13 does not create a catalog entry.

## 2. Make imported metadata visible and reversible

- [x] Decode and test a representative Open Library response containing all
  supported metadata fields.
- [x] Verify that the first returned result is saved automatically.
- [x] Show a short confirmation message after an automatic import, naming the
  saved title and Open Library as the source.
- [x] Add a **View** action that opens the imported book's details.
- [x] Add an **Undo** action that removes the automatically imported book.
- [x] Keep automatic import confirmation-free; do not add a required review
  page.
- [x] Test successful import, View, Undo, and empty/error fallback behavior.

### Acceptance criteria

- A successful scan saves the first Open Library result without a review step.
- The confirmation message identifies the saved title and Open Library.
- View opens the correct imported book.
- Undo removes only that imported book and returns to the collection.
- The details screen shows the metadata returned when it is available.

## 3. Show the running app version

- [x] Add the app version and build number to the target configuration.
- [x] Read the displayed version from the app bundle.
- [x] Add an unobtrusive version label at the bottom of the empty collection.
- [x] Keep the version label visible below a populated collection.
- [x] Add a test for bundle-version formatting or version-provider fallback.

### Acceptance criteria

- The home screen shows the installed version in both collection states.
- Changing the target version changes the displayed value without editing UI
  code.
- The label is readable with VoiceOver and does not obstruct collection
  actions.
