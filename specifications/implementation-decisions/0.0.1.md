# Implementation decisions

These decisions are intentionally small and should guide the first working
version of the app.

## Duplicate ISBNs

Store one book per ISBN. If the user scans an ISBN that already exists in the
catalog, open that book's details instead of adding a duplicate.

## Manual entry

Manual entry supports books with no barcode or a failed Google Books lookup.

- Title is required.
- ISBN and author are optional.
- If a barcode was scanned, prefill the ISBN field.

## Failed metadata lookup

If Google Books cannot return a result—for example because the device is
offline or the ISBN is unknown—open the manual-entry form. A retry flow is out
of scope for the first version.

## Google Books API key

The app uses a Google Books API key for metadata lookup. The key must be kept
outside the codebase and must not be committed to version control. The Android
build should load it from developer-local or deployment-specific configuration,
such as `local.properties` or an environment variable.

## Android baseline

Choose the minimum supported Android version while creating the application.
This can be based on the current Android tooling defaults and camera-library
requirements.

## Local database

Use Room as the Kotlin data-access layer over SQLite. The book catalog remains
stored on the device.
